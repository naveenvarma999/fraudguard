Your data checklist

FieldWhat to provide
AmountA finite number from 0 to 1,000,000,000, in the benchmark’s amount units.
V1 through V28All 28 compatible anonymized numerical features, each between −10,000 and 10,000.
transaction_idOptional for upload. Unique letters, numbers, hyphens, or underscores; up to 64 characters. Missing IDs are assigned by row.
Time / ClassOptional benchmark columns. They are discarded before scoring; labels never become model inputs.

Maximum 100 transactions and 256 KiB per upload. CSV files must have a header row. JSON numerical values must be numbers, not quoted strings.

What this application can—and cannot—tell you

A risk score is an estimate, not proof of fraud. “Pass” means below the selected threshold, not guaranteed safe. The model was evaluated on an old, anonymized research benchmark. It cannot score a raw card number or ordinary bank export, and it has not been validated for live payment decisions. When workspace persistence is enabled, scores, transaction IDs, amounts and aggregate feature counts are retained for 90 days by default. Raw feature vectors are not stored. Review notes and audit events are retained.
